# MemeFight Party — Wave 2.5 Lobby warmup polls

**Date:** 2026-06-04  
**Status:** Approved for implementation  
**Phase:** Wave 2.5 — retention / lobby engagement  
**Depends on:** Party P1 lobby (`waiting` phase), Realtime room poll  
**Does not change:** `party_advance_phase`, caption/vote/reveal flow until host starts game

## Goal

Give players something to do in the **waiting** lobby before the host starts — lightweight A/B/C polls that build energy without affecting scores or game state.

## Success criteria

- Poll UI visible only when `room.phase === "waiting"` and `room.status === "open"`
- Any member can vote once per poll; vote updates visible to all members within ~3s (poll interval + Realtime optional)
- Poll state cleared when host starts game (`party_start_game`)
- No impact on caption timer, templates, or advance RPCs
- English copy in `lib/party/copy.ts`

## Non-goals

- Host-authored custom poll questions (static rotation only in v1)
- Polls during caption/vote/reveal
- Persistent poll history across rematch (reset on rematch with lobby return)

## Data model

### Table `party_lobby_poll_votes`

| Column | Type | Notes |
|--------|------|-------|
| `room_id` | uuid FK `party_rooms` | |
| `poll_key` | text | e.g. `warmup-0` from rotation |
| `user_id` | uuid FK `auth.users` | |
| `option_index` | smallint | 0…n-1 |
| PK | `(room_id, poll_key, user_id)` | one vote per user per poll |

### Poll definitions (client + server)

Static list in `lib/party/lobby-polls.ts`:

```ts
{ key: "warmup-0", question: "…", options: ["…", "…", "…"] }
```

**Rotation:** `poll_key = warmup-${hash(room_id) % polls.length}` — stable for room lifetime until start clears votes.

### RPC `party_cast_lobby_poll_vote(p_room_id, p_option_index)`

- Caller must be room member
- Room `phase = 'waiting'` and `status = 'open'`
- `p_option_index` in range for current poll
- Upsert vote; return tallies `{ option_index: count }[]` and `my_option_index`

### Start game

`party_start_game` deletes all `party_lobby_poll_votes` for room (or TRUNCATE via DELETE).

## API

- `POST /api/party/lobby-poll` — body `{ roomId, optionIndex }` → snapshot with `lobbyPoll` field

## Snapshot extension

```ts
lobbyPoll?: {
  key: string;
  question: string;
  options: string[];
  tallies: number[];
  myOptionIndex: number | null;
} | null;
```

Only populated in `waiting` phase.

## UI

- `LobbyWarmupPoll` in `HostOnboarding.tsx` below reaction bar
- Three option buttons + result bars (%)
- Disabled after vote (show selected state)

## Realtime

Existing lobby poll (2.5s) on `GET /api/party/rooms/[id]` is sufficient for v1. Optional later: broadcast on vote insert.

## Security

- RLS: members SELECT tallies; INSERT/UPDATE own vote only via RPC
- Rate limit: implicit (one vote per poll per user)
